================================================================================
WHAT YOU'RE TESTING TONIGHT (Core Validations)
================================================================================

Reach lets you control Copilot CLI from Telegram on your phone. Tonight,
you're validating the PERMISSION PROMPTING feature — the key new capability
that lets destructive tools (bash, git commit, etc.) prompt for approval.

5 Core Validations:

1. Permission prompt APPEARS when you send a destructive tool
   Example: "bash ls" → inline keyboard with Allow | Deny buttons

2. Permission prompt WORKS when you tap it
   - Allow → tool executes
   - Deny → tool is blocked
   - Both return to normal session state

3. Safe tools DON'T prompt
   Example: "grep -r TODO src/" → runs immediately, no buttons

4. Prompts DON'T TIMEOUT
   You can think for 30 seconds before tapping. It still works.
   (This is a critical ADR-9 design feature — verify it tonight.)

5. CONCURRENT prompts work
   If you trigger 2 destructive tools at once, each gets its own button set.
   Approve/deny one independently of the other.

Full test scenarios in: reach-dogfood-checklist.md §4

================================================================================
WHAT CAN GO WRONG (Rollback)
================================================================================

1. Prompt doesn't appear → Check: REACH_PERMISSION_POLICY=interactiveDestructive
2. Buttons don't respond → Tap again (15s window). Check daemon logs.
3. Daemon crashes → Ctrl+C, then: npm start
4. Session stuck → /remove (in topic), then /new (create fresh)
5. Registry corrupted → Delete %LOCALAPPDATA%\reach\registry.json, restart

All recoveries in: reach-dogfood-checklist.md §6
