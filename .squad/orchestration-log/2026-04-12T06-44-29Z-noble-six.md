## Spawn Context

Investigated `@github/copilot-sdk` v0.2.2 to understand how to bind the Reach bridge layer to the real Copilot CLI SDK. Produced architecture decision record (ADR) documenting findings and recommended adapter pattern.

## Key Findings

1. **Event-based streaming, not AsyncIterable** — SDK emits `assistant.message_delta` events with `{ deltaContent: string }` chunks. Completion signaled by `session.idle` event. Must bridge to `AsyncIterable<string>` via async generator.

2. **No named sessions in SDK** — SDK uses opaque `sessionId` strings internally. But SDK accepts custom `sessionId` on `createSession({ sessionId })`, so we use the friendly session name directly.

3. **Session state persists to disk** — `resumeSession(id, config)` restores conversation history. Maps directly to Reach's lazy-recreation pattern.

4. **Two return shapes for send()** — `send()` returns `Promise<string>` (message ID). `sendAndWait()` returns `AssistantMessageEvent`. Recommend wrapping for streaming semantics.

5. **Permission handler required** — SDK mandates `onPermissionRequest` on `createSession`. Use `approveAll` for personal tool.

6. **SDK manages CLI process** — One `CopilotClient` instance spawns/manages Copilot CLI server via JSON-RPC (stdio by default).

## Recommended Implementation

**Adapter pattern** in `src/copilot/impl.ts`:
- `CopilotSessionFactoryImpl` wraps SDK `CopilotClient`
- `CopilotSessionAdapter` bridges events → `AsyncIterable<string>`
- Relay code unchanged (depends only on factory/session interfaces)
