## Technical Decisions

**Transport Design:**
- In-memory PassThrough streams (vs. mock named pipes) — simpler, deterministic, fast
- Configurable pipe name — enables parallel test execution without name collisions
- Synchronous 'line' event delivery (readline still fires synchronously through PassThrough)

**Message Schema:**
- `hello` for registration (established term from ADR-2, ADR-6)
- `session.registered` for ack (namespaced for clarity in multiplexed protocol)
- `hello` includes `sessionName` for human-readable session identification
- `ping`/`pong` include `sessionId` for self-describing messages
- Streaming protocol: `inject` (daemon → extension) + `stream`/`stream.error` (extension → daemon)
  - `stream` messages include `requestId` for request-response correlation
  - `done: true` on final chunk signals completion

**Heartbeat Harness:**
- Fake-timer friendly — uses `setTimeout`/`setInterval` (test can mock these)
- Does NOT mock `setImmediate` — readline 'line' events still fire synchronously
- Race condition notes: pong-deadline handle must register in `pendingPings` before `_writeTo` is called

## Known Issues / Handoff Notes

**Contract Drift (Expected & Resolved):** Jun and Carter designed independently and landed on different protocols. Both were valid interpretations of ADR-3. Noble Six's ADR-8 resolves in Jun's favor (streaming semantics win).

**Synchronous Transport Gotcha:** In-memory PassThrough delivers data synchronously. The pong-deadline `setTimeout` handle must register in `pendingPings` *before* `_writeTo` is called, or the pong arrives and clears a handle that doesn't exist yet. Real named-pipe I/O is async so this race doesn't occur in production — noted for local integration testing.
