## Technical Decisions

**Service Account Approach:**
- User account (not LocalSystem/NetworkService) — eliminates DACL/integrity-level barrier
- Password prompt at install time (Windows SCM requirement for non-system accounts)
- UPN format preferred for compatibility (`user@domain`)

**User Resolution:**
- `os.userInfo().username` + `process.env.USERDOMAIN` (no spawned processes, no WMI)
- Fast, reliable, no external dependencies

**Password Handling:**
- Prompts via readline with echo suppressed
- Lives in memory during install only — never stored on disk
- Passed directly to node-windows `CreateService` API

**Single-User Scope:**
- Service stops on logoff (expected for personal tool)
- Multi-user scenarios require per-user install (acceptable design decision)

## Impact on Phase 6

**For Carter (Named Pipe Server):**
The named pipe `\\.\pipe\reach-bridge` will now be created in the user-session context, not LocalSystem/NetworkService. This eliminates the DACL/integrity-level barrier that was blocking extension connections. The daemon sees the current user's environment, so `%USERPROFILE%`, `%APPDATA%`, and user-specific paths are correct.

**No breaking changes** — this is purely a service account change. The bridge protocol is unaffected.
