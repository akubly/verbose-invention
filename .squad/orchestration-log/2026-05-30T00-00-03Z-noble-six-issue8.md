## Root Cause Analysis

SDK v0.2.2 changed `session.send()` from returning an async iterable (per v0.1.x) to returning `Promise<string>` (message ID). Streaming now flows exclusively through event emitters. The daemon side (`src/copilot/impl.ts` / `CopilotSessionAdapter`) had been updated to v0.2.2's event-emitter pattern. The extension.mjs had not, creating a split where only the daemon path worked and mirror.input broke.

Additional issue: old code passed bare string `send(text)` but v0.2.2 API requires `send({ prompt: text })` MessageOptions object.

## Decision Records

- **Fix approach:** Replicate the event-emitter pattern from `impl.ts` directly in `streamSdkResponse`. This is the lowest-risk fix (proven pattern, no new abstractions).
- **Alternatives rejected:**
  - Option A (batch mode via `await send()`) — send() returns message ID string, not reply text. Rejected.
  - Option B (wrapper adapter Promise→AsyncIterable) — Unnecessary indirection. Rejected.
- **Backpressure handling:** Original loop used drain-wait. New version writes without drain-wait. Rationale: local pipe, write rate bounded by SDK event delivery, Node.js buffers internally. Can be reintroduced if production back-pressure observed.

## Architectural Findings

**Split adaptation problem:** Two places hold SDK sessions in Reach:
1. **Daemon** (`src/copilot/impl.ts`): Creates via `CopilotClient.createSession()` / `resumeSession()`, wrapped in `CopilotSessionAdapter` (TypeScript-protected).
2. **Extension** (`extension.mjs`): Returns raw SDK `CopilotSession` from `joinSession()` (plain JS, no compile-time safety).

Both must be updated when SDK API changes. This creates a surface for future drift.

**Recommendation for Phase 9:** Extract shared `streamingAdapter.mjs` or minimal typed helper so both paths share one implementation of the event-emitter pattern.
